## Delegating final review

Only the reviewer responsible for a perspective MAY perform a dedicated final review from that perspective.

You MUST plan a dedicated final review when the developer requests one or the task includes a significant change in one of these areas.

- **Business.** Changes the outcome required by a business rule.
- **Technical.** Changes a compatibility guarantee for existing callers, integrations, or persisted data.
- **User experience.** Adds a workflow or changes the steps users must take to complete one.

For all other changes, the agent responsible for the overall task SHOULD verify the result directly.

Choose the review perspective from the task scope before verification starts.
When the result is complete, you MUST delegate each planned review to the reviewer responsible for that perspective.
You MUST give the reviewer the original task, any changes to its requirements made during the work, and the completed result.
Use the assigned reviewer's findings for that perspective.
